# Validated command-buffer timeline diagnosis

This change adds opt-in bounded diagnostics at the three existing commit/wait sites in `Gemma4Runner`: deferred segment flush, direct dispatch and direct pipeline dispatch. `commandTimelineEnabled` defaults to false. Enabling it records host timestamps immediately before/after commit and after completion wait, raw GPU start/end timestamps, and available kernel counts/encode intervals. It adds no command buffers, synchronization, readbacks, completion callbacks, kernels or SSA changes.

`commandTimelineReset(capacity:)` accepts 1–8192 events. The recorder keeps the bounded leading events and reports dropped tail events. `commandTimelineSnapshot()` returns a value trace. `Gemma4CommandTimeline.analyze` rejects incomplete, zero, nonfinite, reversed, overlapping or out-of-host-bound GPU intervals and reports missing sequences, truncation and skipped gap pairs. It never hides invalid times with a clamp or bridges a missing/rejected event to infer an adjacent gap.

Host timestamps convert `mach_absolute_time` through `mach_timebase_info`, the basis documented for `CACurrentMediaTime` in the installed Apple SDK. Metal documents GPU timestamps as host seconds; every recorded event must contain its GPU interval within its own host before-commit/after-wait bounds before deriving quantities. A real three-buffer Metal blit probe passed this containment check. This diagnoses timestamp consistency on this device; it is not clock calibration or compute-occupancy measurement.

## Completed checks

Opus 5.5 authored the exact runtime/helper/test patch. The initial build exposed a missing `@MainActor` annotation on the new test function; its original author supplied that single correction, changing no runtime statement or assertion. Release build then passed in 40.12 seconds. **2,094 Swift/Metal checks passed, zero failed**, including pure timeline rejection/sequence/drop/coding tests and the actual device clock probe. Fable 5.1 accepted source correctness with no blockers; the final evidence review also returned ACCEPT with no blockers. Its interpretation requirements are recorded below.

An independent fixed-protocol driver used the existing model, validated graph and region, and a fresh public verification-only MoE E4/R32 installation plus Q4 width32. It did not relabel or install old executable-bound production artifacts. It exercised the existing modern prepared SSA candidate with all current optimized axes enabled and router divisor1. For raw Hello and canonical English/Korean chat, each arm produced **32 exact greedy IDs and 262,144 finite logits per output**. Serial reference, instrumentation OFF and ON all passed the unchanged normalized `<1e-4` gate and matched the previously frozen baseline IDs. OFF/ON normalized logit differences were exactly zero; the driver did not separately compare Float bit patterns, so it does not certify signed-zero bit identity. The report boolean fields are guard-implied statements, set only after the checks pass. The raw-Hello serial difference was 7.5292e-5, approximately 75% of the unchanged 1e-4 threshold. This is strict diagnostic path verification, not normal production re-forging or admission of a new optimization.

The traced window includes the **31 continuation steps after prefill**. All three retained traces contained **1,147 valid deferred command buffers**, or **37 per token**, and **1,349 encoded kernels per token**. There were no rejected/missing/truncated events. The run took 125.01 seconds including serial/OFF/ON replay; source and driver binary were unchanged throughout.

These are single diagnostic traces with instrumentation and retained output storage, not throughput qualification or a speed improvement. Encode and GPU-end-to-wait-return are overlapping subintervals of the inter-command gap; commit/wait durations also overlap other columns. Do not add them as disjoint costs. GPU command elapsed time includes possible memory stalls and does not establish arithmetic utilization, bandwidth saturation, kernel occupancy or insufficient parallelism. The observed submission gap includes wait-return latency, host scheduling, CPU/router work, encoding and this driver's output storage/loop overhead. It is not CPU busy time or attribution to another process. The full-vocabulary readback and step-boundary driver work are included; those boundary gaps cannot be assigned to a kernel shape. Relevant intra-step gaps require explicit per-step event boundaries before kernel-level attribution.

Outside-only aggregate observations recorded global pageouts +8,217, swapins +229,116 and swapouts +206,175 (16 KiB pages). Counters are cumulative page movement, not current swap footprint or a per-process diagnosis. Outside observations also recorded thermal/battery status and aggregate load; these raw records are in the run receipt. No thermal or performance warning was recorded, and the machine remained on AC power. The previous failed 40.46% and 23.8144% A/A spreads remain failed against the fixed 5% gate. No new matched Ollama ratio or gain claim is established.

## Next implementation boundary

The measured command intervals dominate this diagnostic wall time. Eliminating every observed host gap would therefore leave most of the measured time; host-only work cannot explain a large remaining performance gap by itself. This observation motivates reviewing the actual quantized/expert GPU lowering, but it does not select a winning kernel or prove causation. Bottleneck classification from this paging-active trace is provisional and must be re-derived in a near-zero-swap window before timing evidence can select a hardware candidate. A new candidate may instead be proposed from validated IR/shape and actual pipeline legality without treating this trace as gain or causal proof. Hardware-/validated-IR-derived alternatives need independent component oracles, full strict three-fixture gates and a resource-valid reproducibility control before timing-based selection. Failed staging, router and launch-geometry experiments stay preserved.

The diagnostics remain off by default and do not activate a new optimization. New executables require ordinary artifact lifecycle validation; old source/executable-bound artifacts are never relabeled. Trace serialization with nonfinite raw events requires an explicit nonconforming-float strategy; per-kernel mode can fill the bound quickly and must inspect truncation. Events outside the three runner sites, including initialization and separate component probes, are not traced.
