# Router/shared scheduling diagnostic

The pure planner derives a permutation from the validated canonical Gemma SSA and its reusable RMS statistics plan. It preserves the canonical schedule and digest. The shared input normalization remains first, including its original cached-statistics computation. Router normalization, scale and projection move ahead of the shared MLP, and only the two router input versions move to a synthetic dedicated routerIn buffer. Shared gate/up/activation/down/postnorm follow, then the unchanged CPU router top-k and routed-expert branch.

The analyzer checks exact per-layer windows, geometry, tensor names, value lifetimes, byte ranges and statistics actions. A shared physical-buffer mapping is used by both the executor and the planner, including the gate/up slices of the fused GU buffer. It replays all modeled operations in the original and permuted orders. A negative control without routerIn must fail at the first shared gate because the router clobbers its normalized input. Decoded plans require reverify before use.

The proof covers declared interpreter bindings, byte ranges, logical cache/routing states and statistics slots. It does not prove internal effects of runner primitives or GPU ordering. Runtime integration must allocate genuinely separate scratch, verify actual aliases and shared-primitive write effects, and explicitly order asynchronous command buffers. This is currently an experimental pure analysis; no overlap execution, artifact activation or speedup has been validated.

The proposed runtime keeps par64 attention, v1 E4R32 MoE and every modern setting. It keeps CPU FP64 softmax, deterministic ties and renormalization. It retains all 30 router waits and adds 30 command buffers per token, attempting to overlap host turnaround with the shared MLP. Whether the extra submissions help remains unmeasured. Source counts are not per-site elapsed-time attribution, and GPU command-buffer spans are not utilization.

Validation: the actual Mac Swift release build compiled the analyzer. The author corrected one test-only throwing-expression syntax error; numerical code and proof logic were unchanged. The CPU-only test executable passed 334 checks on the real canonical graph metadata: 30 layer windows, 934 instructions, 30 statistics computes and 60 reuses, stable digest, preserved canonical SSA and malformed/hazard rejection cases. It read no GGUF weights, created no GPU workload and performed no model-file hash. Independent Fable 5.1 review accepted the proof within its stated boundary. Source and tests were authored by the existing authorized Opus 5.5 CLI.

Run: swift build -c release --product router-overlap-pure-tests -j 4, then .build/release/router-overlap-pure-tests --graph /path/to/gemma-graph.json. Hardware correctness and matched normal-path performance gates remain required before this scheduling diagnostic can become a production pass. The rejected phase52 serial-attention SIMD composition and the closed phase38 copy/readback experiment are not retried.
