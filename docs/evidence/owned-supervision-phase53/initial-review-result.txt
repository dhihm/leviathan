**Verdict: BLOCKERS (two), both small fixes in `Supervisor`. Everything else reviewed holds up.**

**Blocker 1: a lost terminal receipt still yields exit 0 and a released lock.** In `Supervisor._write_receipt` a write failure is printed to stderr and swallowed. `Supervisor._exit_code` then returns 0 whenever the in-memory result is success. The design states that exit evidence lives only in the receipt, yet a disk-full or permission failure at the last step produces a run with no receipt and a success exit code. `Supervisor.run` also calls `_release_lock_if_safe` before `_write_receipt`, so this failure leaves no lock and no receipt, which `collect_status` cannot distinguish from a supervisor that died mid-run. Fix: record whether the receipt was actually written, make `_exit_code` return nonzero when it was not, and release the lock only after the receipt write succeeds. The `lockReleased` receipt field then needs to go or be derived differently.

**Blocker 2: an echo failure on the supervisor's own stdout aborts the benchmark.** `Supervisor._handle_line` writes each line to `echo_stream` with echo on by default. If the launching session closes its end of the pipe, or the tty hangs up, that write raises and propagates as a generic error. `Supervisor.run` then enters cleanup and sends SIGTERM to a healthy benchmark, possibly inside the timed window. The run is recorded honestly as an error, but an owned GPU run is killed for a supervisor-side cosmetic failure, which is the opposite of session-loss recoverability. Fix: catch OSError around the echo write only, disable echo for the rest of the run, append a note. Logging and state handling must stay unchanged.

Non-blocking items, in rough priority order:

- **Signal arriving while an except branch runs escapes `run`.** In `Supervisor.run`, the LaunchRefused and generic-exception branches run `_safe_phase` with `_in_cleanup` still False and `_signal_raised` False. A SIGINT there raises out of the except block, cleanup and receipt still happen in the finally, but the exception then leaves `run` uncaught and `main` prints a traceback with `interruptedBy` unrecorded. Setting the guard flag at the top of each except branch closes this.
- **Inherited SIGCHLD ignore breaks exit evidence and the exact-PID guarantee.** SIG_IGN survives exec. If the launcher ignores SIGCHLD, Popen reports ECHILD as exit code 0, and `Popen.terminate` can target a reused PID because the zombie is auto-reaped. Resetting SIGCHLD to default at the start of `run` is a one-line hardening. Related: the poll-before-kill guard in `send_signal` needs Python 3.9 or later.
- **The window is not write-free.** `_handle_line` rewrites `state.json` through temp file plus rename on every line between GO and the end marker. The module docstring says only stdout reads and `poll` happen there. Either amend the docstring or defer state rewrites during `timed_window` and rely on `progress.jsonl`.
- **Identity surviving exec is asserted, not tested.** `TestRealWrapperLifecycle` uses `LiveFakeProcInfo`, so no test shows that start time and ppid of the real Popen child are unchanged after the wrapper execs. The kernel does preserve the fork-time start value, but a darwin-only test reading the real child before START and again after `BENCHMARK_READY` would make recovery's core assumption verifiable.
- **GO write to an already-exited child misclassifies the run.** In `_maybe_send_go`, a BrokenPipeError from the GO write becomes result `error` instead of `exited_nonzero`, although the receipt still carries the exit code. Catching it and setting an explicit abort reason is cleaner.
- **SIGHUP is unhandled.** A terminal hangup kills the supervisor with no receipt while the benchmark survives in its own session. That may be the intended recovery posture, but it should be a deliberate choice. Adding SIGHUP to `_install_signals` would instead produce cleanup plus a receipt.
- **macOS fsync is not a storage barrier.** `write_json_atomic` uses `os.fsync`, which on macOS does not force the drive cache. Only relevant for power loss, not session loss, so F_FULLFSYNC is optional.

Areas reviewed and found sound: the START gate with the durable identity write before release, the byte-wise token read in `wrapper_main` so GO is never consumed, `ProcBsdInfo` layout and the `proc_pidinfo` call signature and return interpretation, `classify_identity` treating start-time and uid mismatch as distinct and ppid drift as unconfirmed, `SelectorLineReader` never blocking past its timeout, the pre-GO and post-end snapshot placement, end-marker-before-GO being ignored, `collect_status` reading only stored PIDs with no signals and no outcome from absence, `_cleanup_child` acting only through the owned Popen handle with no escalation, and lock retention when the child's status is unknown.
